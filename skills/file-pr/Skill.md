# gh ettiquette

Before filing check wether an pr for this issue exists. 

Review the diff locally against origin/main to make sure
its contents match the goal. 

PR titles usually become commit messages, so make sure it is 
concise, human-readable, and explains why the change matters:

Open the description with a simple explanation of the problem
then breifly explain the solution. Don't lead with an implementation
inventory.
