Unified exec is poll-only for the model. A background process can outlive its turn and keep running across turns. When it exits, only a UI/client event goes out. Nothing is written to model history, no new turn starts, and a sleeping model is not woken.

Links below are relative to `https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/`.

## 1. `exec_command` / `write_stdin` parameters and limits (code)
- Limits in `core/src/unified_exec/mod.rs` ([#L73-L82](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/mod.rs#L73)):
  - Minimum yield is 250 ms; an empty poll waits at least 5,000 ms.
  - Maximum yield is 30,000 ms (Windows floor 10,000 ms).
  - Background poll maximum is 300,000 ms by default, configurable via `background_terminal_max_timeout` and never below 5,000 ([config/mod.rs#L3835](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/config/mod.rs#L3835)).
  - `max_output_tokens` defaults to 10,000; output is capped at 1 MiB.
  - At most 64 processes.
- `exec_command` args: `cmd`, `shell`, `login`, `tty` (default false), `yield_time_ms` (default 10,000), `max_output_tokens`, plus permission fields ([handlers/unified_exec.rs#L28-L68](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/handlers/unified_exec.rs#L28)). The yield is clamped to 250–30,000 ms ([mod.rs#L218](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/mod.rs#L218)).
- `write_stdin` args: `session_id`, `chars` (default empty), `yield_time_ms` (default 250), `max_output_tokens` ([write_stdin.rs#L23-L32](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/handlers/unified_exec/write_stdin.rs#L23)).
  - Empty polls are clamped to 5,000–300,000 ms; writes are capped at 30,000 ms ([process_manager.rs#L1016](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L1016)).
  - If `tty` is off, the only input allowed is the interrupt character ([~#L990](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L990)).
- Pruning happens only when a new process is stored and 64 already exist ([#L1726](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L1726)):
  - The 8 most recently used are protected ([#L1779](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L1779)).
  - The least recently used exited process goes first, then the least recently used live one, which is terminated ([#L1227-L1238](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L1227)).
  - There is no idle timeout.
- **Yes, the model can start a long command and poll it later.** A live process is stored before the yield wait ([#L598](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L598)), and the response returns a `process_id`. Calling `write_stdin` with empty `chars` polls it ("Defaults to empty, which polls without writing", [shell_spec.rs#L117](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/handlers/shell_spec.rs#L117)).
- Exception: if managed policy turns off `unified_exec`, a one-shot `exec_command` is registered instead. It has `timeout_ms` (default 10 s), returns no session id, and there is no `write_stdin` ([spec_plan.rs#L1060-L1068](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/spec_plan.rs#L1060)).

## 2. Exit notification: poll-only (code)
- `spawn_exit_watcher` ([async_watcher.rs#L166](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/async_watcher.rs#L166)) waits for exit, then calls `emit_exec_end_for_unified_exec`. That leads to `emit_turn_item_completed` ([events.rs#L577](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/events.rs#L577)), which only runs `send_event(ItemCompleted)` using the turn context of the turn that started the process ([session/mod.rs#L2599-L2639](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/session/mod.rs#L2599)).
- That path makes no `record_conversation_items` call, no pending-input or mailbox push, and no turn start. `core/src/unified_exec/` never references `input_queue` or pending input (grep).
- `TerminalInteraction` events are only sent from inside `write_stdin` ([#L1110-L1123](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L1110)).
- Within one call, output collection stops early if the process exits ([#L1576](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L1576)). That only shortens the current call.
- Inference: the model learns about an exit only when it next calls `write_stdin` and gets `exit_code` with no `session_id`. The TUI shows "background terminal running · /ps" ([status_indicator_widget.rs#L497](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/tui/src/status_indicator_widget.rs#L497)).

## 3. Lifecycle (code, plus inference where marked)
- **Turn end:** nothing is killed. The turn only records a running-process metric ([tasks/mod.rs#L781](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tasks/mod.rs#L781)). Processes persist across turns.
- **Interrupt:** `handle_task_abort` ([tasks/mod.rs#L905+](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tasks/mod.rs#L905)) does not call `terminate_all`. Storing the process before the yield exists so that an interrupt does not kill it ([#L598](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L598)).
- **Explicit kill:** `Op::CleanBackgroundTerminals` → `terminate_all_processes` ([handlers.rs#L60](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/session/handlers.rs#L60), [#L431](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/session/handlers.rs#L431); [process_manager.rs#L1798](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process_manager.rs#L1798)). In the TUI, `/ps` lists and `/stop` (alias `/clean`) stops all ([slash_command.rs#L74-L76](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/tui/src/slash_command.rs#L74), [slash_dispatch.rs#L553](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/tui/src/chatwidget/slash_dispatch.rs#L553)).
- **Session shutdown:** `shutdown_session_runtime` calls `terminate_all_processes` ([handlers.rs#L286-L302](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/session/handlers.rs#L286)).
- **`codex exec`:**
  - On the first completed, failed or interrupted turn it returns `InitiateShutdown` ([event_processor_with_human_output.rs#L323](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/exec/src/event_processor_with_human_output.rs#L323)).
  - It then unsubscribes and calls `client.shutdown()` ([exec/src/lib.rs#L1282-L1305](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/exec/src/lib.rs#L1282)), and the in-process server runs `shutdown_threads` ([in_process.rs#L580](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/app-server/src/in_process.rs#L580)).
  - Inference: background processes die when `codex exec` exits.
- **TUI exit:** it unsubscribes the thread ([thread_routing.rs#L40](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/tui/src/app/thread_routing.rs#L40)), then shuts down the app-server ([startup.rs#L1286](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/tui/src/app/startup.rs#L1286)).
  - Inference: with the in-process server, processes are killed. With a daemon server, the thread unloads 60 s after it has no subscribers and is idle ([thread_lifecycle.rs#L56](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/app-server/src/request_processors/thread_lifecycle.rs#L56), [config/mod.rs#L3840](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/config/mod.rs#L3840)).
- **Kill mechanics:**
  - `UnifiedExecProcess` and the PTY `ProcessHandle` both terminate on Drop ([process.rs#L648](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/unified_exec/process.rs#L648), [utils/pty/src/process.rs#L273](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/utils/pty/src/process.rs#L273)).
  - The PTY killer sends SIGKILL to the process group ([pty.rs#L76-L81](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/utils/pty/src/pty.rs#L76), [process_group.rs#L270](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/utils/pty/src/process_group.rs#L270)).
  - On Linux, pipe-mode children also get `PR_SET_PDEATHSIG` ([pipe.rs#L159](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/utils/pty/src/pipe.rs#L159)).

## 4. `sleep_tool` and `current_time_reminder` (code)
- The tool is `clock.sleep` with one argument, `duration_ms`, between 1 and 12 hours ([sleep.rs#L26-L28](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/handlers/sleep.rs#L26), [#L96](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/handlers/sleep.rs#L96)). The feature is Stable and on by default ([features/src/lib.rs#L973](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/features/src/lib.rs#L973)).
- Being on is not enough for the tool to be registered. In the default `ModelDriven` mode it needs the model's `experimental_supported_tools` to include `"clock"`, or `current_time_reminder.sleep_tool = true`. `mode = "always_on"` forces it ([spec_plan.rs#L1176-L1192](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/spec_plan.rs#L1176)).
- Early wake: it races the timer against `input_queue.subscribe_activity` ([sleep.rs#L108-L133](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/tools/handlers/sleep.rs#L108)). That signal fires only on a user steer into the active turn or an inter-agent mailbox message ([input_queue.rs#L137](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/session/input_queue.rs#L137), [#L269](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/session/input_queue.rs#L269)). **A process exit does not wake it.**
- `current_time_reminder` is UnderDevelopment and off by default ([features/src/lib.rs#L1697](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/features/src/lib.rs#L1697)). When on, it records a CurrentTimeReminder user fragment into history before inference, at an interval defaulting to 1 s ([time_reminder.rs#L156-L210](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/session/time_reminder.rs#L156), [config/mod.rs#L1289](https://github.com/openai/codex/blob/rust-v0.156.0/codex-rs/core/src/config/mod.rs#L1289)).
